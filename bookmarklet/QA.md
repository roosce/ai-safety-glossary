# Bookmarklet Onboarding — Cross-Browser QA (Engineer 4)

**Scope:** desktop-only onboarding funnel for the AI Safety Glossary bookmarklet —
drag install → copy-paste fallback → live demo → per-page click → success indicator.
**Design under test:** Design A (teal highlight tint + trailing ⓘ glyph), `OCCURRENCES = "all"`.
**Acceptance:** pass/fail per desktop browser (Chrome, Edge, Firefox, Safari) + filed issues with repro.

## Pre-QA issues (filed against current `bookmarklet/`)

### QA-1 — Design mismatch: dotted underline, not Design A · **Blocker**
- **Where:** `glossary-core.js:30` — `.glossary-term{border-bottom:1px dotted currentColor;cursor:help}`.
- **Observed:** terms get a 1px dotted underline; **no teal tint, no trailing ⓘ glyph**.
- **Expected:** Design A — teal highlight tint + trailing ⓘ glyph on annotated terms.
- **Repro:** `node build.js`, open `install.html`, click the bookmark, inspect a highlighted term.
- **Fix (E1):** update the term CSS to the Design-A tint + ⓘ and emit it from `build.js` into
  `widget-styles.css` (see QA-3); add the glyph in `makeTermSpan` or via `::after`.

### QA-2 — No `ais-glossary-ready` event · **Blocker for E3 success indicator**
- **Where:** `glossary-core.js:250-263` (`init`) signals success only via the `flash()` toast.
- **Impact:** E3 can't wire `#tryit-status` — there is no event to listen for.
- **Fix (E1):** after annotating, dispatch
  `document.dispatchEvent(new CustomEvent("ais-glossary-ready",{detail:{count}}))` with the
  highlighted-term count (`found` is already computed at `glossary-core.js:259`).

### QA-3 — `build.js` emits no `widget-styles.css` · **Blocker for shared look**
- **Where:** `build.js` writes `bookmarklet.txt` + `install.html`; term/tooltip CSS lives inlined
  as `BASE_CSS` in `glossary-core.js:29-37`.
- **Impact:** no single source of truth — the onboarding demo cannot `<link>` the real widget CSS,
  so the demo and the live widget will drift.
- **Fix (E1):** have `build.js` emit `widget-styles.css` from the canonical term/tooltip CSS and
  have the widget + onboarding page consume the same source.

### QA-4 — No copy-paste fallback UI · **Funnel gap**
- **Where:** `install.html` (generated by `build.js:63-68`) explains the fallback in prose
  ("paste the contents of `bookmarklet.txt`") but ships **no copy button**.
- **Impact:** users whose bookmarks bar is hidden / browsers that block drag-install have no
  one-click path. Contract calls for `#copy-code-btn` + `#bookmarklet-code`.
- **Fix (E2/E3):** render the bookmarklet string into `#bookmarklet-code` and add a working
  `#copy-code-btn` (Clipboard API + textarea fallback).

### QA-5 — Contract DOM IDs absent · **Integration blocker**
- **Where:** `install.html`.
- **Impact:** E3's `onboarding.js` wiring targets (`#demo`, `#install-btn`, `#install-steps`,
  `#tryit`, `#tryit-status`, …) don't exist; the page is a static prototype, not the contracted
  onboarding surface.
- **Fix (E2):** author `onboarding.html` with the contract IDs; retire/replace prototype `install.html`.

### QA-6 — Design-A density on long papers · **Readability (pre-flagged per my brief)**
- **Context:** `OCCURRENCES = "all"` (`glossary-core.js:22`) annotates *every* mention. With
  Design A adding a tint **and** a ⓘ glyph per mention, a long paper (e.g. BlueDot readings, dozens
  of repeats of "AI alignment", "RLHF", "frontier model") will look **speckled** and hurt reading flow.
- **Proposed fix:** keep `OCCURRENCES = "all"` for the tint, but render the **ⓘ glyph on first
  mention per term only**. The `"first"` de-dupe path already exists (`glossary-core.js:122-126`,
  keyed on canonical term), so gating the glyph is cheap — reuse that `seen[]` bookkeeping for the
  glyph rather than for the highlight.
- **Action:** confirm with design during cross-browser run; this is the density check my role owns.
